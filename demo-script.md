# Demo video script (≤ 5 min)

Record with QuickTime (File → New Screen Recording, or ⌘⇧5; turn the microphone on under Options) and narrate. Open these tabs before you start. Everything shown is a real run on the fork.

The main run is **issue #5**, the deliberately vague issue. It goes through every part of the pipeline: a blocking question, the maintainer's answer, a full run, a PR, CI and a posted review.

| # | Time | Show | Say |
|---|---|---|---|
| 1 | 0:00–0:30 | `README.md`, then the component view (`architecture/views/component-view.png`) | "AutoSE turns a GitHub issue into a tested, reviewed PR in six fixed stages. Agents only produce files. A deterministic Python state machine decides every transition. The reviewer runs in its own job with no token and on a different model. A human merges." |
| 2 | 0:30–1:15 | Issue [#5](https://github.com/vishesh312/tinydb/issues/5): the vague text, the `/autose` comment, then the bot's "needs more information" comment with Q-1 and Q-2 (run [45431061462](https://github.com/vishesh312/tinydb/actions/runs/45431061462)) | "This issue is vague on purpose. The Analyst found two questions that change what the tests should assert, so S1 stopped with `autose:needs-info` instead of guessing." |
| 3 | 1:15–2:00 | Further down issue #5: the maintainer's answer, the second `/autose`, then the status comment's timeline | "After the maintainer answers, the run starts again. S1 spec, S2 design, S3 code and S4 tests each passed their check on the first attempt. The tester's 6 new tests fail on the base commit, which proves they test the change." |
| 4 | 2:00–2:45 | Actions run [45432006950](https://github.com/vishesh312/tinydb/actions/runs/45432006950): the gate → build → round1 (ci, review, post) → finalize graph. Open the build job's steps | "Prepare and publish hold the GitHub token. The agent step in the middle has no token, only the Codex login, and it is deleted afterwards. The review is a separate job with read-only permissions." |
| 5 | 2:45–3:30 | PR [#21](https://github.com/vishesh312/tinydb/pull/21): files changed, green CI, the AutoSE review (APPROVE, checks the reviewer ran) | "The reviewer saw only the issue and the diff, ran its own probes, and approved. The verdict is posted as a comment; the bot never merges. The PR also passes all 4 hidden tests we wrote before the run." |
| 6 | 3:30–4:15 | PR [#14](https://github.com/vishesh312/tinydb/pull/14): the AutoSE review with REQUEST_CHANGES and "1 confirmed" | "The reviewer earns its place here. PR #14 passes all its hidden tests, but the reviewer found that `update(doc_ids=['nope'])` crashes while `get` returns None, and a separate verifier confirmed it. On the five seeded PRs it got all five verdicts right and did not obey the prompt injection in SP5." |
| 7 | 4:15–5:00 | `results/runs.md`, ADR-014 and ADR-015, then `report.pdf` §5 | "All five issues produced PRs that pass 19 of 19 hidden tests. Two decisions shaped this: running the agents on a Codex subscription instead of the API, and Claude Ship's Find→Verify review pass. What we learned: a shared subscription quota is not a per-run budget, so the next design needs a global quota governor." |
