# ADR-014: Agent harness is the Codex CLI on a ChatGPT subscription, routed per role; Claude Code stays selectable

- Status: Accepted (2026-11-24). **Supersedes ADR-011** (harness) and **amends ADR-006** (models, what "cost" means)
- Decision area: Agent harness (supports D1, D5, D6, D8, D9)
- Deciders: Team (Vishesh Saraswat)

## Context

ADR-011 chose `claude -p --bare` billed through the Anthropic API, and everything was built and tested offline against it. Before any live run, the student decided **not to use the API** and to use subscriptions they already hold instead: the OpenAI Codex CLI (ChatGPT login) and the Google Antigravity CLI `agy` (Google login). The `pi` agent with Codex OAuth was a third option. This is a constraint on the project, not a performance finding. It changes the harness, the models, the security envelope and the meaning of the budget, and it has to keep ADR-011's seven requirements as far as possible.

We checked the candidates against those requirements with live probes on 2026-11-24 (codex-cli 0.172.0, agy 1.5.15, pi 0.84.4):

| Requirement (ADR-011) | `codex exec` | `agy -p` | `pi -p` (openai-codex) |
|---|---|---|---|
| 1 Tool restriction from outside | OS sandbox: `-s read-only` / `workspace-write`, **network off** by default, `approval_policy=never`. No per-command allowlist | `--sandbox` terminal restrictions; **network not blocked** (probe fetched example.com) | `--tools` allowlist; no OS sandbox |
| 2 Structured final output | `--output-schema` (strict-mode schema) + `-o last.txt`, verified | `--json-schema` → `structured_output`, verified | none (prompt-only) |
| 3 Per-call cost cap + usage | usage in `turn.completed` events; no $ cap (subscription) | usage in the JSON envelope; no $ cap | usage; no cap |
| 4 Good built-in tools | yes (shell + apply_patch) | yes | yes |
| 5 No repo-loaded config | `--ignore-user-config --ignore-rules --ephemeral`, `project_doc_max_bytes=0` (AGENTS.md ignored, verified by canary) | `--disable-slash-commands`; workspace rules not fully controllable | `--no-context-files --no-extensions --no-skills` |
| 6 Same harness locally and in CI | yes: npm package, file-based login (`CODEX_HOME/auth.json`) | Mach-O binary + Google OAuth; no documented headless CI login | yes |
| 7 No GitHub write / control flow | yes | yes | yes |

## Decision

1. **Default backend: Codex CLI** for every role, invoked by `CodexRunner` (`workflow/autose/backends.py`) as `codex exec --ephemeral --ignore-user-config --ignore-rules --json -m <model> -s <sandbox> -c developer_instructions=<system prompt> -c project_doc_max_bytes=0 -c approval_policy=never --output-schema <strict schema> -o <file> -`, with the task on stdin. The system prompt goes in as `developer_instructions`, so it stays separate from the untrusted, fenced task.
2. **Sandbox replaces tool allowlists.** A role gets `workspace-write` (cwd plus `--add-dir`, no network) only if the original DESIGN §6 table gave it Edit/Write (Developer, Tester, Builder, Reviewer probe dir). Every other role is `read-only`. The orchestrator's path allowlists, staged-diff checks and final path gate are unchanged and stay the authoritative control.
3. **Backend per role, chosen in config:** `AUTOSE_BACKEND` sets the default, and `AUTOSE_BACKEND_<ROLE>` overrides one role. `claude` (the ADR-011 runner, unchanged) and `agy` remain selectable. `agy` is used only for the read-mostly Reviewer, because its sandbox does not block network. The cross-vendor reviewer (agy, Claude Opus 4.6) is an E1 arm.
4. **Models (amends ADR-006):**
   - Builders (Analyst, Architect, Developer, Tester, Builder): `gpt-6.1-sol`.
   - Judge: `gpt-6-luna` (changed to `gpt-6.1-sol` at low effort; see the revision note below).
   - Reviewer and Verifier: `gpt-6-astra`. This is a *different* model from the builders, which preserves ADR-008's "different model" rule within one vendor.
   - E1's friendly reviewer uses the builder model.
5. **Budget becomes notional (amends ADR-006).** A subscription has no per-call price. Each call is priced from its token counts using an assumed list-price table (`NOTIONAL_PRICES`, overridable). The $10 run cap, the per-call caps (checked after the call) and the reviewer reservation therefore still bound a run. We report this as "list-price-equivalent $", and report tokens as the real consumption of subscription quota.
6. **CI credential:** the repo secret `CODEX_AUTH_JSON` holds a copy of `~/.codex/auth.json`. It is written to `$RUNNER_TEMP/codex-home` only inside the tokenless agent step and deleted in an `if: always()` step.

### Revision note 1 (2026-11-24): judge model

The judge default in `workflow/autose/config.py` was changed from `gpt-6-luna` to the builder model `gpt-6.1-sol` at **low** effort, after the first live run in which, according to the comment beside the setting in `config.py`, the `gpt-6-luna` judge twice failed a spec on test-layout nitpicks rather than on testability. That run is recorded in `results/runs.md` (local, issue-1 / codex, judge gpt-6-luna) with its judge output in `results/local/issue-1-luna-judge/` (`judge.json`, `summary.json`); the rerun with the new judge passed S1-S4 first attempt and 4/4 hidden tests (`results/local/issue-1-codex/`). The judge's per-call cap ($0.05 notional) and effort (low) are unchanged. The judge now shares a model with the Analyst whose ACs it rates; it still runs in a separate single call with no tools and sees only the AC list (ADR-007), so independence rests on context and prompt rather than model for this check.

### Revision note 2 (2026-11-24, evening): smaller models to save quota

The first live day used up the ChatGPT usage limit in about 25 minutes. That limit is shared across all Codex models on the account, and five concurrent CI runs plus local experiments on `gpt-6.1-sol` / `gpt-6-astra` hit it. A probe at 21:22 IST confirmed the limit is account-wide: `gpt-6.1-terra` was refused with the same "try again at 11:49 PM" message. The defaults therefore move to smaller models, which use less quota per token:

- Builders (Analyst, Architect, Developer, Tester, Builder) and the low-effort Judge: `gpt-6.1-terra`.
- Reviewer and Verifier: `gpt-6-luna`. This is still a different model from the builders, so ADR-008's "different model" rule holds. E1's friendly reviewer follows the builder model.
- The notional price for `gpt-6.1-terra` is an assumed midpoint, (1.25, 0.125, 7.50) $/1M tokens, set in `NOTIONAL_PRICES`.

Every run recorded in `results/` before this note used `gpt-6.1-sol` builders and a `gpt-6-astra` reviewer and verifier. The old models are still available with `AUTOSE_MODEL_<ROLE>`. Risks: a smaller reviewer may miss what `gpt-6-astra` caught in E1, notably the SP3 approach defect. `gpt-6-luna` was too strict *as a judge* before the judge prompt was clarified, and has not yet been tested as a reviewer. The check for both is to re-run `experiment/scripts/run_e1.sh` (independent arm) once the quota resets.

## Alternatives considered

- **Keep the API (ADR-011).** Rejected by the student's constraint: no API spend.
- **agy for everything.** Rejected for builders: there is no file-based headless login for hosted Linux runners, its sandbox does not block network, and it is a 230 MB arm64 macOS binary here.
- **pi with Codex OAuth.** It has good isolation flags and the same models, but no structured-output enforcement and no OS sandbox. That would mean our own schema-retry loop and losing the network block, so Codex directly is strictly better for us.
- **A self-hosted runner on the student's Mac,** to use both logins. Rejected: the orchestrator runs agent-written tests outside any sandbox, which would mean arbitrary code from LLM output running on a personal laptop.

## Consequences

Positive:
- Agent shell commands now run with **no network**, which closes much of ADR-009's "key exfiltration through test code" risk for commands run by agents (canary `sandbox`: `UNSET NET_BLOCKED`).
- There is no marginal $ cost, so E1 and E2 can run more repetitions.
- The whole runner layer is backend-agnostic. All backends produce one envelope shape, so the routing, ledger and checks did not change.

Negative:
- **No hard per-call cap.** A call stops only at its timeout (20 min), and the cost check runs after the call. One runaway call can exceed its notional cap. The run cap still stops the next call.
- **Coarser permissions.** Codex has no "pytest only" rule. A workspace-write agent can run any command inside the sandbox. The path gates catch the effects.
- **The credential cannot be spend-capped.** The orchestrator runs agent-written tests in the same step, outside the Codex sandbox and with network, and `auth.json` is readable at a known path. A malicious test could exfiltrate the ChatGPT session. Mitigations: only writers trigger runs (ADR-010), fork PRs are rejected, the file is deleted after the step. The orchestrator's own check subprocesses are **not** sandboxed (`AUTOSE_SANDBOX=1` only installs bubblewrap; wrapping checks in `codex sandbox` is future work). Rotating the login (`codex login`) revokes it.
- **Refresh-token rotation.** If CI refreshes the token, the student's local login may need `codex login` again.
- **Results are not comparable with a Claude-API baseline.** ADR-006's model claims are now about GPT-6.x models.

## Answers to the brief's questions

- **D5 Tools: how is each agent limited to what it needs?** Through the Codex OS sandbox (`read-only` for Analyst, Judge, Architect and Verifier; `workspace-write` with network off for Developer, Tester, Builder and the Reviewer's probe directory), plus the unchanged orchestrator path gates, which remain the authoritative control. Agents still have no MCP and no GitHub access (ADR-005).
- **D6 Models: which model for each role, and why?** `gpt-6.1-sol` for builders, `gpt-6-astra` for the Reviewer and Verifier so the grader is a different model from the builders (ADR-008), and the builder model at low effort for the single-call judge (revision note above). Cost is reported as notional list-price-equivalent dollars plus real token counts.
- **D9 Safety: budgets and secrets.** The run cap and reservation still bound a run in notional dollars; the subscription's own usage limit replaces the provider spend limit. The credential risk is stated under Consequences.

## How we will know if this is wrong

- The canary fails in CI, for example because a flag changed or the Linux sandbox is unavailable.
- Structured-output failures exceed 1 in 10 calls in `ledger.jsonl`.
- A call's notional cost exceeds twice its cap. If so, add a token-based stop using `--json` event streaming.
- The friendly and independent reviewers behave the same in E1. That would mean a different model within one vendor is not independent enough, and the cross-vendor arm (agy) should become the default reviewer.
