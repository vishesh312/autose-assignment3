## Summary

Add membership behavior to TinyDB and named tables so callers can check for a document ID or a matching query with the `in` operator. Unsupported operands must raise TypeError; changes to contains() and large-table performance are outside this issue.

## Approach

Add Python membership special methods to Table and TinyDB. Table dispatches integer operands and callable operands to the existing contains() method; TinyDB forwards membership to its default table, as it already does for iteration and length. This preserves the existing storage and query behavior without changing contains().

## Files

- `tinydb/table.py` (Table.__contains__): Add def __contains__(self, item: object) -> bool alongside the existing special methods. First check isinstance(item, int) and return self.contains(doc_id=item); otherwise, if callable(item), return self.contains(item). For all other operands, raise TypeError('Membership requires an integer document ID or a callable query'). Integer dispatch takes precedence for objects that are both integers and callable. Do not alter contains().
- `tinydb/database.py` (TinyDB.__contains__): Add def __contains__(self, item: object) -> bool alongside the existing forwarded special methods. Return item in self.table(self.default_table_name), so default-table membership uses the configured table class and propagates its result or exception.
